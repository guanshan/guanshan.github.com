技术主线 Thesis

技术主线 Technical Thesis

在企业级 Agent 平台这件事上，我关心的几个核心命题。 A few core convictions that shape how I build enterprise agent platforms.

01

不确定 vs. 确定性 Non-determinism vs. determinism

LLM 推理能力突出，但具有内在不确定性；企业交付所要求的是确定性、安全性与可解释性。Agent 平台的核心价值不在于模型调用本身，而在于以工程化方式将这种不确定性收敛至企业可接受的边界之内。 LLMs are capable but inherently non-deterministic, whereas enterprise delivery demands determinism, security, and explainability. An agent platform's core value lies not in invoking the model itself, but in engineering that non-determinism back within boundaries the enterprise can accept.

02

Agent 不是聊天机器人 Agents are not chatbots

我倾向于将 Agent 定义为一类包含非确定性决策节点的任务执行系统，而非对话界面的延伸。任务规划、工具调用、状态持久化、人工确认、失败补偿与执行审计，是 Agent 在企业生产环境中稳定运行的前置条件。 I define agents as task-execution systems containing non-deterministic decision points, not as extensions of a chat interface. Task planning, tool use, durable state, human-in-the-loop checkpoints, failure compensation, and execution auditing are the prerequisites for agents to operate reliably in production.

03

平台的核心不是模型调用 The platform isn't the model call

企业级 Agent 平台的核心命题，是建设完备的权限、安全、编排、可观测、评测、成本与交付治理体系，而非聚焦于模型调用本身。正是这些非展示性的工程层，决定了模型能力能否被稳定交付。 The hard part of an enterprise agent platform is not the model-invocation layer, but the underlying infrastructure: permissions, security, orchestration, observability, evaluation, cost, and delivery governance. It is this non-customer-facing engineering layer that determines whether model capability can be reliably delivered.

04

平台应当沉淀，而不是堆叠 Platforms should compound

成熟的 Agent 平台应具备能力沉淀机制：将客户场景中反复出现的问题抽象为可治理、可复用的平台原语，使平台能力在持续使用中收敛，单次交付成本逐步下降。 A mature agent platform should embed a capability-compounding mechanism: every recurring problem in customer delivery distilled into a reusable, governable primitive, so the platform converges over iterations and the marginal cost of delivery declines.

能力方向 Focus

技术方向 Focus & Expertise

围绕企业级 Agent 平台的六个能力方向，从运行时到产品化交付。 Six capability tracks around the enterprise agent platform — from runtime to productization.

Agent 运行时架构 Agent Runtime Architecture

让 Agent 在企业环境中具备可预期、可恢复、可审计的执行能力：任务规划、工具编排、状态持久化、异步执行、人工确认、失败补偿、执行轨迹。 Predictable, recoverable, auditable agent execution for enterprise environments: task planning, tool orchestration, durable state, async execution, human-in-the-loop checkpoints, failure compensation, and full execution traces.

大模型应用工程化 LLM Application Engineering

把模型能力转换为可衡量、可演进、可控成本的工程资产：Prompt 与上下文工程、结构化输出、模型路由、评测闭环、成本治理。 Turning model capability into measurable, iteratable, cost-bounded engineering assets: prompt and context engineering, structured outputs, model routing, evaluation loops, and cost governance.

检索增强与知识工程 RAG & Knowledge Engineering

让企业知识在 LLM 链路中既能被理解，也能被控制：文档解析、分块策略、混合检索、Rerank、Query Rewrite、引用还原、权限感知检索。 Making enterprise knowledge both usable to LLMs and controllable by the business: document parsing, chunking strategies, hybrid retrieval, reranking, query rewriting, citation alignment, and permission-aware retrieval.

企业级平台架构 Enterprise Platform Architecture

按企业级标准组织、部署与运营 AI 能力：多租户、权限模型、服务治理、API 网关、配置管理、灰度发布与可观测体系。 Organizing, deploying, and operating AI capabilities to enterprise standards: multi-tenancy, permission models, service governance, API gateways, configuration, progressive rollout, and observability.

工具协议与执行沙盒 Tool · MCP · Sandbox

在赋予 Agent 执行能力的同时维持安全边界：工具协议设计与注册、权限校验、云沙盒、浏览器自动化、代码执行隔离。 Granting agents execution capability while preserving security boundaries: tool protocol design and registry, permission enforcement, cloud sandboxes, browser automation, and isolated code execution.

产品化与平台交付 Productization & Delivery

将客户交付中反复出现的问题沉淀为平台能力，使单次解决方案转化为可复用、可治理、可规模化交付的产品原语。 Distilling recurring delivery patterns into platform primitives — converting single solutions into reusable, governable, and scalable product capabilities.
